**P11에서 지역 정의 제거 > 중간 등식 생략 > 반복 사실 공통화 순으로 heartbeat 결과가 좋았다. 공통화는 토큰이 줄어도 HB가 증가했다.** 이는 이 정리의 세 후보에 대한 비교이지 전략 전체의 일반 순위가 아니다.

## 조건과 사전 고정

- 모든 후보의 부모는 benchmark 원본. S1 결과에 S2/S3를 누적하지 않았다.
- Lean v4.31.0, ArkLib `c1712f6c496d0aef04f09bae42aec13811b3273f`, 기존 로컬 checkout과 설치된 의존성을 사용했다.
- 명령당 timeout 180초, 각 body 2회. 작성한 후보는 조건당 1개이며 수리 후보는 만들지 않았다.
- 가설을 먼저 등록하고 원본·후보·diff·가설 해시, 소스·manifest·toolchain·검증기·공유 helper 해시를 고정했다. 실행 전후 fingerprint를 확인했다.
- 원본 전체 파일에서 선언을 유일하게 교체했다. 원본 대비 새 공리 없음은 별도 `review.json`에서 검사한다. raw `result.json`의 `passed`만으로 최종 선택 가능성을 판정하지 않는다.
- HB는 기존 `#count_heartbeats` 계측, 토큰은 기존 대회 `proof_length` 재구현이다. tiktoken 토큰·wall time과 혼용하지 않는다.
- 기존 `selected.lean`, 이전 JSON/log/snapshot, 발표의 초기 측정 표는 변경하지 않았다. 이번 후보는 자동 채택·제출되지 않았다.

## 전략별 해석

### S1: 제거 가능한 계산을 먼저 없애기

[P11-S1 diff](P11-S1/candidate-01.diff)는 `P₀_coeffs` 하나만 제거한다. `P₁_coeffs`와 실제 refinement 다항식 정의는 유지한다. 1,854 HB와 124토큰이 줄었다. 과거 B는 계수 정의 **두 개**를 제거한 후보였으므로 이번 S1은 B와 동일하지 않으며 기존 best 갱신도 아니다.

재사용할 교훈은 “명시적으로 참조되지 않는 지역 정의를 제거 후보로 찾는다”이다. 이름 미참조만으로 유효성을 보장하지 않으며 자동화·지역 문맥 의존성을 검사한다.

### S2: 중간 계산 경로 단축

[P11-S2 diff](P11-S2/candidate-01.diff)는 전개형 중간 식 세 행을 제거하고 다음 `ring`으로 직접 연결한다. 789 HB와 62토큰이 줄었다. 과거 B 기반 C 실험의 786 HB와 **3 HB 차이**가 있다. 부모가 원본인지 B인지, 실행기·계측 문맥이 같은지 구분해야 하므로 “C의 고유 비용은 항상 786”이라고 해석하면 안 된다. 이 결과와 과거 값을 섞어 새 상호작용 대비를 계산하지 않는다.

### S3: 짧아져도 계산량이 늘 수 있다

[P11-S3 diff](P11-S3/candidate-01.diff)는 동일한 지수 등식을 공통 scope의 `h_shared_pow`로 만들고 두 `h2`에서 사용한다. 23토큰이 줄었지만 295 HB가 늘었다.

주의할 점은 공통 증명을 `congr 1; omega`로 작성했고 원래 각 위치는 `rw [h1]`였다는 것이다. 따라서 이 결과는 **이 공통화 구현 전체**의 효과이며, “재사용 자체가 295 HB를 추가했다”는 원인 분해는 아니다. 두 `h1`은 제거 전략을 섞지 않으려고 남겼다. 또한 공통화 대상은 다른 실험에서 제거 가능성을 확인한 계수 정의 내부에 있다. 최적화 탐색이라면 삭제 가능한 블록을 공통화하기 전에 삭제부터 검토하는 것이 합리적이다.

## P12와 환경 차단

P12 원본 검사 두 번 모두 다음 오류로 종료했다.

```text
object file '.../ArkLib/Data/CodingTheory/ProximityGap/DG25/Basic.olean'
of module ArkLib.Data.CodingTheory.ProximityGap.DG25.Basic does not exist
```

[1회차 로그](../metrics/structural-pilot-2026-10-25/P12-S1/baseline-1/check.log) · [2회차 로그](../metrics/structural-pilot-2026-10-25/P12-S1/baseline-2/check.log).

기존 실행기의 raw 상태는 `failed`지만 원인을 확인한 요약은 `environment_error`다. 원본 실패 뒤 후보 호출은 guard가 차단했으므로 **Lean 후보 검증은 0회**다. 준비한 proof의 수학적 실패로 세거나 HB를 0으로 채우지 않는다. 동일한 환경 오류를 2회 반복한 것은 새 근거를 늘리지 못했다. 다음 실행에서는 원본의 환경 오류를 확인하면 해당 정리 전체를 중단해야 한다. 배치 종료 코드 0도 모든 조건의 성공을 뜻하지 않는다. 각 결과·로그를 직접 감사했다.

P3/P6의 지정 toolchain은 기본 elan 경로에 없고 기록된 lake-env 경로에는 ArkLib/cslib만 있었다. 전 시스템 탐색 결과가 아니라 확인한 경로 안에서의 가용성 판단이다. [환경 확인 기록](../metrics/structural-pilot-2026-10-25/environment-check.json). 설치·다운로드는 수행하지 않았다.

## 구현·재현 경계

기존 `run_experiments.py`의 `problem()` 범위에 P3/P6/P12를 추가하고 새 문제는 명시적인 격리 output을 요구하도록 했다. 기존 CLI는 P8/P11 그대로다. **지원 번호 추가는 해당 문제의 실행 검증 완료를 뜻하지 않는다.** 파일 교체·공리 파싱·HB 계측은 복제하지 않고 기존 함수를 재사용한다.

`run_pilot.py`는 현재 준비한 P11/P12 변환과 2회 반복만 실행한다. 모델 호출·자동 수리·대시보드 제출은 하지 않는다. Python 회귀 테스트 29개와 파일럿 테스트 7개, 총 36개가 통과했다. 입력 manifest 4개와 실행 결과의 후보 해시·환경 식별자를 대조했다.

실행 명령 형태는 다음과 같다. 아래는 **이미 사용한 절차의 기록**이며, 그대로 다시 실행하면 overwrite/중복 실행 보호로 거부된다.

```sh
python3 run_pilot.py prepare --problem 11 --strategy S1 --repo <고정 ArkLib 경로>
python3 run_pilot.py evaluate --problem 11 --strategy S1 --kind baseline --repetition 1
python3 run_pilot.py evaluate --problem 11 --strategy S1 --kind candidate --repetition 1
```

재실험은 기존 원장·inputs·hypothesis를 고치지 말고 새 실험 ID와 출력 위치를 가진 실행기로 분리해 fingerprint를 다시 고정해야 한다. 현재 파일럿은 범용 세션 실행기가 아니므로 자동 재개 인터페이스는 없다. 기록된 절대 경로는 당시 provenance이지 다른 머신에서 사용할 고정 경로가 아니다.
