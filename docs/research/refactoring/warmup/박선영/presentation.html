WEEK 4 / 이번 주 질문

작게 고치는 대신,
증명 구조를 바꾸면 더 줄어들까?

이번 주에는 작은 변환을 먼저 비교하고,
P8·P11에서 큰 구조 변경을 별도로 탐색했습니다.

출발점만 이어받았습니다.
P8은 기존 선택 proof, P11은 지난주 B+A+C best입니다.

지난주: P11의 지역 정의·계수 계산·중간 등식을 정리했습니다. 이번 주: 남은 큰 개선 기회를 찾습니다.

발표 메모

지난주에는 P11의 작은 변경들을 분리해서 효과를 확인했습니다. 이번 주에는 그 방식만으로 충분한지 궁금했습니다. 먼저 작은 변환을 비교한 다음, 증명 골격이나 긴 계산 블록 자체를 바꾸는 탐색으로 범위를 넓혔습니다.

발표 메모

이번 주 첫 실험은 원본에서 한 가지씩 바꿔보는 것이었습니다. 정의 제거와 중간 등식 생략은 도움이 됐습니다. 반면 반복 사실을 묶은 후보는 토큰은 줄었지만 HB는 늘었습니다. 그래서 같은 계산을 짧게 쓰는 것뿐 아니라, 그 계산이 필요한지와 아예 대체할 수 있는지를 보기로 했습니다.

02 / 탐색 범위를 넓히되 검증은 유지

변경은 크게,
비교 기준은 그대로

이번에 허용한 변경

  • 증명 전체의 재귀·귀납 골격 변경
  • 긴 계산을 기존 보조정리로 대체
  • 필요한 증거를 직접 구성

유지한 확인 절차

  • 같은 명제·같은 파일 문맥
  • 전체 파일 검사·새 공리 없음 확인
  • 원본·시작 best·최종 후보 각 3회

“원본보다 좋은가?”와 함께
“이미 개선한 best보다 더 좋은가?”를 비교했습니다.

기존 로컬 Lean v4.31.0 · 수리 포함 문제당 최대 6개 후보 · 실제 Lean 실행은 직렬. 작은 파일럿과 같은 시작점·예산의 정책 비교는 아닙니다.

발표 메모

이번 성능 탐색은 원본에서 다시 시작하지 않았습니다. P8은 기존 선택 후보, P11은 지난주 best에서 출발했습니다. 두 시작점도 이번에 다시 측정했습니다. 후보를 크게 바꾸더라도 명제와 검증 기준은 그대로 유지했고, 마지막 비교는 세 번씩 확인했습니다.

재귀 호출과 전술 조립을
귀납 가설과 직접 증거로 바꿨다

이전

축약 증거에 귀납 → 귀납 가설 사용
→ 공통 항·양쪽 증거를 한 번에 구성

첫 후보는 토큰이 늘었지만,
후속 등식 처리 정리로 HB와 토큰을 모두 줄였습니다.

발표 메모

P8은 두 방향으로 축약된 결과가 다시 같은 곳에서 만날 수 있음을 증명합니다. 이전에는 작은 부분에 같은 정리를 재귀 호출하고 여러 전술로 증거를 조립했습니다. 이를 명시적 귀납과 직접 구성으로 바꿨습니다. 처음에는 길어졌지만, 등식의 대입과 추론 가능한 항까지 정리하자 토큰 증가도 해소됐습니다.

귀납 변경도, 직접 구성도 도움이 됐습니다.
둘을 합친 뒤 등식 처리까지 정리하면 380 HB입니다.

결합 감소량은 단독 감소량의 합보다 24 HB 컸습니다. 특정 tactic의 고정 비용을 측정한 것은 아닙니다. 대조군 실패 1개와 수리본도 예산에 포함했습니다.

발표 메모

왜 줄었는지 확인하려고 귀납만 바꾼 후보와 직접 구성만 바꾼 후보를 따로 만들었습니다. 각각 1,000과 773 HB였고, 둘을 합치면 429였습니다. 따라서 큰 감소를 귀납 하나의 효과로 설명하면 안 됩니다. 마지막 정리를 더한 최종 후보가 380입니다.

05 / P11 · 두 fiber 점의 차이가 1임을 증명

긴 좌표 계산 대신,
이미 증명된 구조를 사용했다

이전 · 계산을 직접 전개

  1. 두 점을 각각 기저의 합으로 표현
  2. 인덱스·타입 변환·bit 값을 정리
  3. 같은 나머지 합이 지워짐을 증명

변경 후 · 기존 보조정리 활용

첫 점 = 공통 부분
둘째 점 = 첫 기저 벡터 + 공통 부분
첫 기저 벡터 = 1

따라서 두 점의 차이는 1.

계산을 조금씩 줄인 것이 아니라,
같은 결론을 주는 기존 정리로 블록 전체를 대체했습니다.

기존 best 38,337 HB / 1,379토큰 → 21,010 HB / 966토큰. 대상보다 앞선 fiber 정리와 기존 의존성의 기저 정리를 사용. 새 공리 없음.

발표 메모

P11에는 두 점의 차이가 1임을 확인하는 긴 계산이 남아 있었습니다. 그런데 앞부분의 보조정리가 이미 두 점을 공통 부분과 첫 기저 벡터로 표현해주고 있었습니다. 이 결과를 사용하면 공통 부분을 빼고 첫 기저 벡터가 1임을 적용하면 됩니다. 타입 변환을 하나씩 줄이기보다 그 계산 블록을 통째로 대체한 것이 핵심입니다.

07 / 어디까지 확인했나?

성공한 두 사례와
일반화된 전략은 다르다

확인한 것

  • 같은 명제로 전체 파일 검증 통과
  • 원본 대비 새 공리 없음
  • 최종 결과 3회 동일

아직 확인하지 않은 것

  • 다른 정리·다른 Lean 버전의 효과
  • 같은 예산으로 비교한 정책의 우열
  • 공식 점수·실제 실행 시간 개선

큰 구조 탐색 후보: P8 6개, P11 2개(실패·수리 포함). 실패 2개는 보존. P12는 원본 의존성 오류, P3/P6는 환경 미준비로 미실행. 독립 실행기 재검토는 도구 오류로 미완료이며 직접 점검·테스트·실제 Lean 검사를 수행했습니다.

발표 메모

이번 결과는 두 정리의 한 버전에서 확인한 사례입니다. 같은 전략이 여러 정리에 통한다거나, 작은 변경보다 항상 우수하다고 말할 수는 없습니다. 실패한 후보도 두 개 있었고 모두 기록했습니다. 다른 정리로의 전이와 버전 호환성은 다음 검증 과제입니다.

08 / 정리와 다음 실험

“어떻게 짧게 쓸까?” 전에,
“이 계산을 그대로 해야 할까?”

P8에서는 증명 골격과 증거 구성을,
P11에서는 계산 블록의 대체 가능성을 확인했습니다.

  1. 바꿀 블록의 가정과 결론을 먼저 읽기
  2. 직접 구성·기존 보조정리로 대체 가능한지 찾기
  3. 적용 조건을 고정하고 다른 정리에서 확인하기

기존 선택 proof·제출 상태는 자동 변경하지 않았습니다. 이번 실험의 조건과 실패까지 다음 탐색 근거로 남깁니다.

상세 결과·실행 근거 · 작은 변환 파일럿 · 전체 발표 메모 · 이전 통합 자료

발표 메모

이번 주에 얻은 결론은 무조건 크게 바꾸자는 것이 아닙니다. 작은 전술을 줄이기 전에, 그 계산을 그대로 해야 하는지부터 보자는 것입니다. 입력과 결론이 같은 기존 정리가 있는지, 증거를 더 직접 구성할 수 있는지 확인하고, 다음에는 이 적용 조건을 다른 정리에서도 검증하려고 합니다.
