웜업 15문제의 증명을 수정하며 Lean 검증 결과와 토큰·heartbeat(HB)를 기록했다. 이전에 선택해 둔 증명(이하 출발 증명)에서 시작해 65개 후보를 시험했고, 대표 버전에서 40개가 통과하고 25개가 실패했다. 출발 증명의 작성자와 파일·커밋은 [출처 목록](evidence/warmup15-20261026/starting-manifest.json)에 정리했다.

## 실험 방법

[실행 코드와 재현 방법](evidence/warmup15-20261026/README.md)에 입력, 검사기 버전과 실행 명령을 정리했다.

1. 출발 증명, 명제, 라이브러리 버전과 평가기를 해시로 고정했다.
2. 작은 tactic 교체, 기존 정리 재사용, 중복 증명 공유 등을 시험했다.
3. 원문 전체 파일을 Lean으로 검사하고, 오류가 난 후보는 수정해 다시 검사했다.
4. 선택할 후보는 원본·출발 증명과 각각 3회 측정하고 지정 버전에서도 확인했다.
5. 평균 점수와 버전 통과 여부를 보고 후보를 선택했다. 통과·실패 기록은 함께 저장했다.

작업 정리에는 paperthin의 `readchk`·`ponytail`·`mandela`·`sip`을 사용했다.

## 시험한 변경

| 범위 | 시험한 변경 | 확인한 조건 |
|---|---|---|
| P01–P04 | 단순화 규칙 삭제, 귀납 증명의 직접 항 구성, 기대 타입 명시 | 귀납 가정과 타입을 유지하며 토큰·HB 비교 |
| P05–P06 | 미분 가능성 사실 공유, `simp` 인수 삭제, 목록 조건의 직접 증명, 보조정리의 정규형 변경 | P05의 C3 가정과 P06의 비가환 곱 순서 유지 |
| P07–P09 | 생성자 직접 적용, 합류 증명 분해, 전이와 관계 증명 의무 분리 | P09 쌍모사의 두 방향 확인 |
| P10–P12 | 기수 부등식의 기대 타입 명시, 인덱스 경계 정리 재사용, fiber 평가 공유, 튜플 복원 정리 적용 | 의존 타입의 인덱스와 목표 식의 표기 확인 |
| P13–P15 | 산술 자동화를 기존 정리로 대체, 연속 재작성 결합, `ring1`과 합 보존 증명 | 토큰·HB와 평균 점수 비교 |

P05에서는 마지막 `simp` 호출을 필요한 규칙만 쓰는 `simp only`와 명시적 소거로 바꿨다. 앞서 통과한 `Pi.sub_apply` 삭제도 결합해 3회 측정했다. C3 가정과 명제는 유지했다.

```lean
simp only [k, div_eq_mul_inv, pow_two, mul_inv_rev, one_mul,
  mul_assoc, mul_left_comm, mul_comm]
rw [mul_left_comm 𝓕.μ₀, mul_inv_cancel_left₀ 𝓕.μ₀_ne_zero]
```

P06에서 보조정리의 정규형을 바꾼 후보는 435토큰/HB 15,329였다. 목록 조건을 직접 증명한 후보는 472토큰/HB 13,721이었다. 두 후보 모두 출발 증명 450토큰/HB 14,127보다 평균 점수가 낮아 출발 증명을 사용했다.

P11에서는 인덱스 경계의 수동 산술 증명을 기존 정리로 바꿨다. 첫 후보는 `Fin 2`의 0을 자연수로 읽는 타입 변환에서 실패했고, `Fin.val_zero`를 단순화에 넣어 수정했다. 선택한 `index-lemma-repair`는 지정된 세 버전에서 통과했다. 두 fiber 평가를 공유한 후보는 등식 방향과 부분타입의 값 변환이 맞지 않아 실패했다.

P12에서는 수동 튜플 복원 증명을 `Fin.snoc_init_self`로 바꿨다. 정리를 바로 적용한 첫 시도는 `simp made no progress`로 실패했다. `← Fin.init_def`로 표기를 맞춘 뒤 다시 적용한 후보가 통과했다.

## 참고 문헌

아래 문헌에서 국소 수정, 정리 재사용, 비용 비교에 관한 아이디어를 참고했다. 이번 실험은 고정된 15문제의 편집 후보를 시험한 기록이다. 논문의 학습·검색 시스템 전체를 구현하거나 성능을 재현한 실험은 아니다.

- [LeanPolish](https://arxiv.org/abs/2609.38384)의 국소 교체 후 재검증 흐름과 [Lean Refactor](https://arxiv.org/abs/2605.20244)의 다목적 선택 방식을 참고했다. P05와 P07–P09의 편집도 전체 파일 검사 후 토큰·HB로 비교했다.
- [Bidirectional Elaborators à la Carte](https://arxiv.org/abs/2607.09564)의 기대 타입을 통한 정보 전달을 참고해 P03·P04·P10·P11에서 타입 명시와 직접 항 구성을 시험했다.
- [Recycling Algebraic Proof Certificates](https://arxiv.org/abs/2507.20267)의 증명 재사용 아이디어를 P05·P06·P11·P12의 보조 증명에 참고했다. P06에서는 비가환 곱 순서를 유지했다.
- [LeanGraphSearch](https://arxiv.org/abs/2610.22339)는 관련 정리와 의존성을 찾는 방법의 참고로 읽었다. P12에 사용한 정리는 [고정 Mathlib의 `Fin.snoc_init_self`](https://github.com/leanprover-community/mathlib4/blob/fabf563a7c95a166b8d7b6efca11c8b4dc9d911f/Mathlib/Data/Fin/Tuple/Basic.lean#L593)다.
- [Agda/PTS 합류 증명](https://arxiv.org/abs/2607.20188)과 [Beluga/π-calculus 전이 증명](https://arxiv.org/abs/2607.12652)을 읽고 증명 공유와 의무 분리를 P08·P09에서 시험했다. 이번 대상은 Lean의 SKI·CCS 정리다.
- [비용·품질을 고려한 Lean 증명 탐색](https://arxiv.org/abs/2606.04883)은 시도 중단과 방법 전환의 참고로 읽었다. 해당 논문의 토큰 비용 대용치와 이번 HB는 서로 다른 지표다.

## 측정 조건

공통 평가기 버전은 `c18ec56682462847e2f4d8b6d60aa79ec071a10b`다. 명제, 원문 전체 문맥, 후속 선언과 허용 공리(`propext`, `Classical.choice`, `Quot.sound`)를 확인했다. HB는 원시 카운터를 1,000으로 나눈 내림값이고, 토큰은 증명 본문의 구문 토큰이다.

`추가 점수 = 50 × ((출발 토큰 − 새 토큰) / 원본 토큰 + (출발 HB − 새 HB) / 원본 HB)`

분모인 원본과 출발·새 후보는 같은 환경에서 측정했다. 버전이나 측정 경로가 다른 HB는 섞지 않았다. P12는 유한 기수 `#(...)` 표기를 허용하는 Somi full-source v2 경로로 검사해 공통 14문제 평균에서 제외했다. 증명 실패와 환경 준비 실패는 따로 기록했다.

모델 호출 비용은 계측하지 않아 문제당 $3 조건 충족 여부는 확인하지 못했다. 별도 유료 생성 API 호출은 없었다. 이 결과는 로컬·CI 측정값이며 공식 Arena 점수나 모델 생성 성공률을 뜻하지 않는다. 15문제 밖의 성능과 증명의 최단 여부도 확인하지 않았다.
