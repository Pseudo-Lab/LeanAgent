01 / 수집 범위

원문 문맥과 실행환경을 연결한 정리 코퍼스

각 출처의 고정 Git 커밋에서 이름 있는 theorem·lemma를 추출했다. 명제, 증명, 원문 파일·문맥 위치, 버전과 SHA-256을 연결했다. def·instance·익명 example와 매크로 생성 정리는 수집 대상 밖이다.

02 / 증명 길이

대부분은 짧고, 긴 꼬리가 평균을 끌어올린다

주 분포는 직접 sorry가 없는 := by 증명이다. 길이는 Arena와 같은 어휘 토큰 규칙으로 세며, 시작의 by를 포함한다. 줄 수, 문자 수, 모델 API 토큰이나 Lean 실행 비용과는 다른 값이다.

출처별 길이 구간의 비율

가로축: 증명 토큰 구간 · 세로축: 해당 출처 주 모집단 대비 % · 모든 출처에 같은 0–40% 세로축 사용

길이의 대표값과 꼬리. P90은 90%의 증명이 그 길이 이하인 지점이다.
출처증명 수중앙값평균P90P99최대

분위수는 순위 (N−1)×q에서 선형 보간했다. 빈 분포는 ‘—’로 표시한다. PutnamBench 원본 672개는 모두 직접 sorry를 포함하므로, 완성 증명의 길이가 0인 것이 아니라 주 분포의 대상이 없다.

긴 증명의 비중과 토큰 집중도를 함께 본다. 출처별 길이 상위 약 5%(경계 동률 포함)가 차지하는 전체 증명 토큰 비중은 다. 이 비중은 저장·읽기 분량의 집중도를 뜻하며, 검증 시간의 비중은 아니다.

03 / Warm-up의 위치

Warm-up 15개는 어느 정도 긴가?

같은 출처의 주 분포에서 각 Warm-up 길이 이하인 증명의 비율을 계산했다. 예를 들어 99%라면 그 출처 증명의 약 99%가 해당 Warm-up보다 짧거나 같은 길이다.

번호출처정리토큰출처 내 누적 백분위

PutnamBench 13–15번은 별도 Arena 완성 참조 증명이다. 미완성 원본 코퍼스와 섞지 않아 백분위를 계산하지 않았다. LeanPool에는 Warm-up이 없다. 이 분포는 본 대회의 출제 확률이나 문제 난이도의 척도가 아니다.

토큰 계산기를 그대로 쓰면 왜 14/15만 일치하는가?

기존 공개 함수의 명제 경계 탐색기는 Warm-up 11번 명제 안의 let P_i :=를 증명 시작으로 오인해 2,219를 반환했다. 추출된 정확한 명제 경계를 사용하는 계산은 공개값 1,906을 포함해 15/15를 재현했다. 이번 재집계는 이 경계가 확인된 길이 레코드를 사용한다. 공개 서버에서 새로 평가한 결과는 아니다.

04 / Tactic 사용

출처마다 반복되는 증명 구조가 다르다

한 증명에 해당 tactic이 한 번 이상 감지되면 ‘사용’으로 센다. 색과 숫자는 사용 증명 비율이다. 한 증명에서 여러 tactic을 사용하므로 열의 합은 100%가 아니다. 소스 문자열의 정적 근사 집계이며 실제 실행 횟수를 측정한 값은 아니다.

Tactic을 사용한 증명 수 / 출처별 주 모집단

합산하면 보이지 않는 패턴

전체를 증명 수로 가중해 합산한 비율과, 비어 있지 않은 5개 출처의 비율을 같은 비중으로 평균한 값을 비교했다. 작은 출처의 simp_all·grind 패턴이 합산에서는 희석된다.

증명 수 가중 합산출처 동등 평균

통계가 알려주는 실험의 출발점

Strata에서는 귀납과 반복 단순화, PhysLib·ArkLib에서는 재작성·단순화, CSLib에서는 grind를 포함한 자동화 사용을 살펴볼 근거가 된다.

빈도가 곧 병목은 아니다. 비용 원인을 확인하려면 같은 정리·같은 실행환경에서 한 가지 변경 전후의 heartbeat를 측정해야 한다.

왼쪽 비교는 항상 by 주 모집단을 사용한다. 동등 평균은 다른 질문에 대한 기술통계이며, 더 정확한 전체 사용률이라는 뜻은 아니다.

05 / 이번에 추가한 분석

문자열 중복과 파일 편중을 확인했다

기존 길이·tactic 요약에 더해, 정리별 내보내기 레코드를 다시 읽어 증명 문자열 SHA-256 중복과 파일별 집중도를 계산했다. 동일한 증명 문자열은 같은 수학 문제를 뜻하지 않으므로, 원본 정리를 삭제하거나 하나의 문제로 합치지 않았다.

동일 증명 문자열 1개만 남긴 길이 분포와의 민감도 비교. 모든 값은 출처 내 by 주 모집단 기준.
출처주 모집단고유 문자열중복 초과분200토큰 이상 중복 초과분중앙값 원본 → 고유

중복 초과분 = (전체 레코드 수 − 고유 proof SHA 수) / 전체 레코드 수. 공백·주석까지 같은 원문 문자열만 일치로 센다. 같은 중복 그룹에 속한 모든 레코드의 비율이나 의미적·명제적 중복률이 아니다. 같은 짧은 전술을 다른 정리에 적용한 경우도 포함한다.

LeanPool: 짧은 공통 증명이 분포에 영향을 준다

중복 초과분은 , 고유 문자열당 한 번만 세면 중앙값이 로 바뀐다. 200토큰 이상에서는 중복 초과분이 다.

이는 분포가 문자열 반복에 민감하다는 관찰이다. 고유 문자열 분포가 ‘참된 난이도 분포’라는 뜻은 아니다.

같은 파일에서 너무 많이 뽑지 않기

각 출처 주 모집단 중 증명이 가장 많은 10개 파일의 점유율
출처관련 파일 수상위 10개 파일 비율

Strata는 상위 10개 파일에 가 모인다. 반복 실행의 표본을 파일·모듈 단위로 나누면 특정 문맥에 과도하게 맞춘 결론을 줄일 수 있다. 여러 파일 사이의 공통 의존성은 이 통계로 제거되지 않는다.

06 / 후속 실험 표본

길이 하한과 출처별 상위 5%를 함께 보자

길이가 긴 증명을 우선 읽기 위한 필터다. 첫 기준은 200토큰 이상, 둘째는 출처별 길이 상위 5%다. 같은 길이 척도의 하한 필터이므로 교집합은 더 엄격한 쪽을 적용한 결과다.

출처주 모집단200토큰 이상상위 5% 경계상위 5% 수교집합

상위 5%는 내림차순 ceil(N/20)번째 길이를 경계로 삼아 동률을 모두 포함한다. 선형 보간한 P95와 정의가 다르며, 정확히 5%보다 조금 많을 수 있다. 슬라이더는 내장된 전체 길이 히스토그램으로 정확히 재집계한다.

출처·길이 구간을 나눠 선택

긴 증명만으로 일반화하지 않는다. 짧음·중간·김 구간과 출처별 표본 수를 먼저 정하고 원본 명제와 문맥을 함께 보존한다.

파일·문자열 반복을 표시

같은 파일이나 같은 증명 문자열이 여러 번 들어가면 따로 표시한다. 가이드 작성용과 평가용 문제를 나눌 때도 함께 고려한다.

환경부터 원본으로 확인

Lean·라이브러리 커밋·의존성·검색 경로를 고정하고 원본부터 검증한다. 추출된 코드 조각만으로 독립 실행이 된다고 가정하지 않는다.

후보 목록에는 기존 Warm-up 1–12번도 포함된다. 새로운 평가 표본을 만들 때는 이 항목과 이미 사용한 문제를 구분해야 한다. 후보 수가 검증 성공 수, 예상 출제 수 또는 개선 가능 문제 수를 뜻하지 않는다.

07 / 근거와 재현

기존 결과를 보존하고, 같은 레코드에서 다시 계산했다

HTML에는 집계 데이터를 내장했다. 파일 하나로 오프라인 열람·출처 선택·후보 재집계·CSV 저장·인쇄가 가능하다. 원본 코퍼스, 이전 통계와 Lean 증명은 수정하지 않았다.

기존 조사에서 가져온 항목

6개 출처의 수집 범위·버전·추출 방식, 길이 분포, Warm-up 공개 길이 보정, tactic 근사 집계, 200토큰·상위 5% 후보와 Strata 검증 기록.

이번 실행에서 다시 확인한 항목

압축 조각·스냅샷 해시, 대입형 길이 레코드 개와 30개 분포 히스토그램, 전체 출처 선언 레코드 개의 개수·tactic 사용 수. 문자열 중복·파일 편중·출처 가중 민감도는 새로 계산했다.

이번 실행에서 하지 않은 것: 원문을 Lean AST로 새로 추출하기, proof 문자열의 토큰 재계산, Lean 컴파일·커널·공리 검사, heartbeat 측정, 모델 호출. 저장된 레코드의 집계 일치 확인과 새 환경에서의 증명 재검증을 구분한다. 관측된 코퍼스의 기술통계이므로 무작위 표본에 대한 유의확률이나 신뢰구간을 붙이지 않았다.

다른 컴퓨터에서 보고서 재생성

# LeanAgent 저장소 루트에서: 포함된 통계로 HTML / CSV 재생성
python3 docs/research/refactoring/corpus/권주원/evidence/corpus-survey/build_report.py --render-only

# 전체 통계 재계산: 별도로 준비한 원본 집계 입력 경로 지정
python3 docs/research/refactoring/corpus/권주원/evidence/corpus-survey/build_report.py \
  --results-root /absolute/path/to/corpus/results

Python 3.9 이상과 표준 라이브러리만 사용한다. --render-only는 저장된 통계의 표시를 재생성하며 통계를 다시 계산하지 않는다. --results-root는 별도 입력 레코드에서 통계를 재계산하고 입력 해시·기존 분포와 대조한다. 대용량 원시 입력은 이 문서 묶음에 포함하지 않았으며, 필요한 파일과 해시는 근거 README에 기록했다. 원문 추출부터 다시 수행하려면 출처별 지정 Lean·의존성을 별도로 준비해야 한다.
