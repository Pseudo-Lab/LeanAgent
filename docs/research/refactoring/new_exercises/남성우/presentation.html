WHY

수리에서 시작해, 정상 증명의 불필요한 단계도 검사

기존 로컬 수리는 오류가 난 곳을 고치는 역할이 중심이었습니다. 이번에는 정상 증명에도 삭제와 짧은 대체 증명을 시도해, 추가 모델 호출 없이 개선 가능한 부분을 찾습니다.

검증할 가설

기존 후보에도 중복 단계나 간단한 자동 tactic으로 대체할 수 있는 블록이 남아 있을 수 있습니다.

채택할 근거

명제·문맥 보존, 전체 파일 검증, 새 공리 없음, 지정 버전 검사와 최종 종합 점수 개선입니다.

DESIGN

동일한 출발 증명에 A만 추가

대조군은 이전 실험에서 선택된 proof body를 새로 검증·계측한 결과입니다. 실험군은 그 동일한 body에 A를 적용합니다. 모델 후보 생성은 다시 실행하지 않았습니다.

원본 기준선 → 기존 선택 증명 → AST 구간 추출 → 삭제·대체 → 전체 검증 → 계측·버전 검사 → 최선 선택
  • Warm-up 15문제 전체를 집계하되, P8은 기존 사용자 결정에 따라 원본만 보존합니다.
  • 문제당 최대 24회 제안, 최대 3라운드. 큰 sequence 2개와 개별 tactic 2개를 우선 선택합니다.
  • 원래 3개 테스트 JSONL은 탐색·정책 조정에 사용하지 않았습니다.
IMPLEMENTATION

Lean의 AST 위치를 사용하고, 최종 판정은 전체 파일에서

Lean parser의 Syntax에서 UTF-8 byte 범위를 읽습니다. 문법 노드 중 지원하는 sequence와 줄 전체 tactic만 수정합니다. 실제 의존관계를 분석하는 C는 구현하지 않았습니다.

삭제와 대체

삭제 → simp? → exact? → aesop? → assumption → rfl. Strata는 aesop?을 건너뜁니다. 탐색 제안은 명시적 증명으로 추출해 다시 검증합니다.

보존 조건

proof body 밖의 원문은 고정합니다. 원본보다 공리가 늘어난 후보, 검증 오류와 미계측 후보는 선택하지 않습니다. 더 좋은 후보가 없으면 기존 최선 또는 원본을 유지합니다.

초기 파일럿에서 일반 텍스트의 제안 위치 누락과 큰 블록 편중을 확인했습니다. JSON 진단과 구간 유형별 배분으로 수정했으며 파일럿은 성과 집계에서 제외했습니다.
